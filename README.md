# LESNet: Leaky Entity Softmax Network

LESNet is a layer for sets of entities with a given relation between them. For receiver `i`, partner `j` and slice `k`,
the pair value is `v_ijk = leaky(a_i + b_j + pf_ij · E + c)`, the weights are the softmax of `v` over the partners `j`,
and the output is `y_ik = leaky(Σ_j w_ijk v_ijk)`. This repository holds the fused CUDA kernels (all-to-all and
neighbour-list layouts), the baselines, the experiments of the accompanying paper and the scripts that turn the raw
results into every table and figure.

The paper is `paper/PAPER.md` (also `paper/PAPER.html`, with the figures inlined).

## Layout

| directory | contents |
|---|---|
| `lesnet_cuda/` | the CUDA extension (`kernels.py`), the model, a float64 oracle, correctness tests and kernel tools |
| `paper/` | synthetic tasks, models and baselines, training and sweep scripts, benchmarks on real data, table and figure generation, the paper text and the raw results |
| `fluid/` | native SPH solver, data generation, learned simulators, evaluation and an interactive viewer |

## Requirements

Python 3.11, PyTorch 2.4.1 built for CUDA 12.4, an NVIDIA GPU, the CUDA toolkit (`nvcc`; 12.9 was used) and a host
compiler (MSVC 2022 on Windows, `gcc` on Linux). Install the Python packages with `pip install -r requirements.txt`.
The extension is compiled on first use by `torch.utils.cpp_extension` into `lesnet_cuda/build/`. Set
`TORCH_CUDA_ARCH_LIST` to the compute capability of the GPU (the code defaults to 7.5, a GTX 1660 Ti). On Windows,
run the scripts from a shell in which the MSVC compiler is on the path (a "x64 Native Tools" prompt).
All reported measurements were made on one GTX 1660 Ti (mobile, 6 GB) in fp32.

## Build and test

```
python lesnet_cuda/tools/build_ext.py
python lesnet_cuda/tests.py            # values and every gradient against the float64 oracle; prints PASS
python lesnet_cuda/tests_sizes.py      # odd shapes, relation widths 1-8, N up to 512 (all-to-all) and 4096 (list)
```

## Use

```python
import sys; sys.path.insert(0, "lesnet_cuda")
from model import LESNet

net = LESNet(cin=16, width=128, depth=4).cuda()
y = net(x, coords, mask)                        # all-to-all:  x (B, N, 16) -> y (B, N, 128)
y = net.local(x, coords, mask, k=24)            # the 24 nearest partners of every entity
y = net.local(x, coords, mask, k=32, radius=0.07)
```

`coords (B, N, 2)` are positions (the layer sees only relative positions, through the relation vector), `mask (B, N)`
marks which slots hold an entity. Partner lists and relations of your own can be passed as `nbr=` and `pf=`; see
`lesnet_cuda/README.md`.

## Data

* Top-quark tagging: download `train.h5`, `val.h5` and `test.h5` from Zenodo (DOI 10.5281/zenodo.2603256) into
  `paper/data_toptag/` and run `python paper/toptag_prep.py` (needs `h5py` and `hdf5plugin`).
* MNIST and CIFAR-10 are downloaded by torchvision on first use (into `paper/bench/data/`).
* Cora and CiteSeer (Planetoid `ind.*` files) and Tiny Shakespeare are included in `paper/bench/data/`.
* Fluid trajectories are generated by `python fluid/gen_data.py` and `python fluid/gen_data.py --v2` (seeded).

## Reproducing the tables and figures

The raw results of every run are included. From them,

```
cd paper
python aggregate.py        # results/*.jsonl, results/bench, results/toptag_v2, ../fluid/out -> results/tables.md, figures/*.png
python build_paper.py      # text/*.md + tables -> PAPER.md, PAPER.html
```

Section 10 of the paper lists which script produces which result. A run of any sweep is resumable: running it again
only fills in the runs that are missing (for example `python paper/sweeps.py main`). The two fluid figures that show
trajectories (`fluid_strips_v2.png`, `fluid_speed_bins.png`) are rendered from the trained simulators, which are not
stored in this repository; `fluid/figures.py` and `fluid/analysis_speed.py` rebuild them after the simulators are
trained with `fluid/run_v2.py`.

## Names

The paper's names map to the code as follows: LESNet is `les`, the graph network is `gnn`, GENConv is `gen`, the
all-to-all layout is the "dense" kernel in `kernels.py`, and the neighbour-list layout is the "list" kernel.
